Эмпирический анализ временной сложности алгоритмов сортировки: сортировка обменом (пузырьком) и сортировка вставками.

## 3. Реализованные алгоритмы

### Сортировка пузырьком

Используется оптимизированный вариант с флагом `swapped`. Если за проход не произошло обменов, алгоритм завершает работу досрочно.

- лучший случай: `Θ(n)`;
- средний случай: `Θ(n²)`;
- худший случай: `Θ(n²)`;
- дополнительная память: `O(1)`;
- устойчивая: да.

### Сортировка вставками

Элементы последовательно вставляются в уже отсортированную левую часть массива.

- лучший случай: `Θ(n)`;
- средний случай: `Θ(n²)`;
- худший случай: `Θ(n²)`;
- дополнительная память: `O(1)`;
- устойчивая: да.

Обе функции не изменяют исходный список: внутри создаётся его копия.

## 4. Методика эксперимента

Для генерации используется `random.Random` с фиксированным seed, поэтому эксперимент воспроизводим. Каждый алгоритм получает один и тот же исходный массив.

Время измеряется с помощью `time.perf_counter()`. Каждый замер выполняется 5 раз, итогом является медиана. После каждого запуска результат проверяется сравнением с `sorted(data)`.

В измерение не включаются генерация массива, проверка и построение графика.

## 8. Анализ

В основном эксперименте размер случайного массива увеличивается в 2 раза. Для квадратичной зависимости теоретическое значение отношения `T(2n)/T(n)` стремится к 4. На практике отношение не обязано точно равняться 4 из-за накладных расходов интерпретатора Python, работы кэш-памяти процессора, фоновых процессов и особенностей конкретного запуска.

Отношение `T(n)/n²` удобно использовать как дополнительную проверку: при выраженном квадратичном характере оно не должно систематически возрастать или убывать на порядок при увеличении `n`.

Дополнительное задание М4 показывает влияние структуры входных данных. Сортировка пузырьком с флагом и сортировка вставками имеют линейный лучший случай на уже упорядоченных данных. Для обратно упорядоченных данных обе получают близкий к худшему случай. Почти упорядоченные данные особенно благоприятны для сортировки вставками, поскольку число необходимых сдвигов связано с числом инверсий.

## 9. Вывод

В работе реализованы сортировка пузырьком с досрочным завершением и сортировка вставками. Для обоих алгоритмов теоретически характерна квадратичная временная сложность в среднем и худшем случаях, а лучший случай имеет линейную сложность.

Экспериментальная часть позволяет проверить квадратичный характер роста времени на случайных данных. Дополнительный эксперимент М4 показывает, что структура массива существенно влияет на фактическое время работы, особенно у адаптивных алгоритмов.

Для больших массивов квадратичные алгоритмы становятся неэффективными; на практике для таких задач применяются алгоритмы со сложностью порядка `O(n log n)` и гибридные алгоритмы.

## 10. Контрольные вопросы

### 1. Сформулируйте задачу сортировки. Приведите три примера применения в бизнес-информатике.

Сортировка — перестановка элементов последовательности в соответствии с заданным отношением порядка. В бизнес-информатике она применяется, например, для сортировки клиентов по сумме покупок, транзакций по времени и товаров по цене или рейтингу.

### 2. Дайте определения O, Ω, Θ.

`O(g(n))` — асимптотическая верхняя оценка роста функции.  
`Ω(g(n))` — асимптотическая нижняя оценка.  
`Θ(g(n))` — точная асимптотическая оценка по порядку роста: функция одновременно имеет верхнюю и нижнюю оценку `g(n)`.

### 3. Что такое лучший, средний и худший случаи? Какие данные являются худшими для сортировки вставками?

Лучший случай — вход, на котором алгоритм выполняет минимум работы; средний — ожидаемая трудоёмкость на рассматриваемом распределении входов; худший — вход, требующий максимальной работы. Для сортировки вставками худшим является массив, упорядоченный в обратном направлении.

### 4. Как `swapped` влияет на сложность пузырьковой сортировки в лучшем случае?

Если за проход не произошло ни одного обмена, `swapped` позволяет завершить алгоритм. Поэтому на уже отсортированном массиве выполняется один проход, то есть лучший случай имеет `Θ(n)` сравнений.

### 5. Что такое инверсия? Как число инверсий связано с трудоёмкостью сортировки вставками?

Инверсия — пара индексов `i < j`, для которой `A[i] > A[j]`. В сортировке вставками число сдвигов элементов непосредственно связано с числом инверсий: чем их больше, тем больше перемещений требуется.

### 6. Что означает устойчивость сортировки?

Устойчивая сортировка сохраняет взаимный порядок элементов с одинаковыми ключами. Это важно, например, при последовательной сортировке записей по нескольким полям.

### 7. Почему используется `perf_counter()`?

`time.perf_counter()` предназначен для измерения коротких интервалов времени и предоставляет высокое разрешение. Для бенчмаркинга он подходит лучше, чем обычное системное время.

### 8. Почему берётся медиана?

Медиана меньше зависит от единичных выбросов, вызванных фоновыми процессами операционной системы и другими случайными факторами, чем среднее арифметическое.

### 9. Почему алгоритмы с одинаковой асимптотикой могут работать с разной скоростью?

Асимптотика описывает порядок роста, но не постоянные множители и накладные расходы. Различия возникают из-за числа сравнений и перемещений, характера доступа к памяти и реализации операций.

### 10. Оцените время сортировки 1 млн элементов.

Для квадратичного алгоритма увеличение размера от `n` до `1 000 000` приводит к огромному росту числа операций порядка `n²`. Поэтому прямой запуск такой сортировки на миллионе элементов может занимать очень длительное время и не является практичным. Точную оценку по одному небольшому эксперименту без экстраполяции конкретной аппаратной системы давать некорректно.
